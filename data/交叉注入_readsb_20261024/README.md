# 交叉注入 A/B — readsb 直采 — 2026-10-24

**问题**：第三方 AGC 把 IF 增益接管后（人为制造越界），守卫能否把它拉回来？代价多大？

**结论**：
- **A 段**（无扰动）交叉平均 **−1.64%** ⇒ 守卫在域内零打扰；
- **B 段**（注入 AGC）交叉平均 **+353.13%** ⇒ 无守卫的臂报文塌到 1/4.5；
- 纠正延迟 **108–117 s**（由收敛门禁决定，不是轮询周期）。

## 实验设计

两机同时、2×2 交叉，每臂 **12 min**：

| 阶段 | 扰动 | `.84` | `.85` |
|---|---|---|---|
| A1 | 无 | **on** | off |
| A2 | 无 | off | **on** |
| B1 | 注入 `agcon` | **on** | off |
| B2 | 注入 `agcon` | off | **on** |

- 拓扑：readsb 独占 SDR 直采，观测源 `stats.json`。
- 注入：对 **off 臂**发 `agcon`（第三方 AGC 接管 `0x0d`/`0x13`）。
- 稳态窗：跳过每阶段前 **240 s**（`noise` 是 60 s 级累加平均，注入后要等收敛）。
- 判据（预注册）：`msg/s` 取 `total` 累计计数器首尾差；
  `c = 128·10^(noise/20)`，可行域 [1.3, 20]。
- 效应 = (正向 + 反向)/2，消机器偏置。

## B 段：注入 AGC（测收益）

| 阶段 | ON 臂 | OFF 臂（注入后） | 相对差 |
|---|---|---|---|
| B1 | `.84` 21.4 msg/s（c 6.59，越界 0%） | `.85` 5.8（c **39.79**，区间 33.67–48.11，越界 **100%**） | +296.96% |
| B2 | `.85` 20.1（c 2.61，越界 0%） | `.84` 3.3（c **46.79**，区间 36.08–62.69，越界 **100%**） | +409.30% |

OFF 臂的 `c` 一路涨到 40–63，正好落在"悬崖 40 码"附近 ⇒ 报文塌到 3.3–5.8 msg/s。

## 纠正过程的分解（为什么延迟是 1–2 min）

以 B1 的 `.84` 为例，把 ON 臂拆成两段：

| 窗口 | 样本 | msg/s | c 均值 | 越界% |
|---|---|---|---|---|
| 塌陷期（注入 → 首次动作） | 4 | **2.2** | 56.24（42.88–64.89） | 100% |
| 恢复后（动作 +120 s → 末） | 26 | **21.4** | 6.59（4.44–8.26） | 0% |

- 首次动作在注入后 **117 s** 落下（B2 的 `.85` 是 **108 s**），一次 `AGCOFF + 写码` 成功：
  `[agcoff rc=0 tries=1 | set 0c rc=0 tries=1]`；
- 延迟**不是轮询慢**（间隔 15 s），而是**收敛门禁**：注入后 `c` 在缓慢漂，
  近 5 个样本极差必须 ≤3 dB 才允许判工况（见 `docs/02-判据与阈值.md §8`）；
- 一次动作、无反复 ⇒ 门禁没有造成振荡。

**这就是"宁可晚 100 s，也不在暂态里乱动"的代价与收益**：
100 s 的延迟换来整个生产期零误动作。

## 读这份数据要注意

1. `valid/s` 与 `msg/s` **恒等** ⇒ 看 `msg/s` 即可。
2. `pos/msg ≈ 6%`（结构性），`pos` 的噪声是 `msg` 的 2–3 倍。
3. B 段 OFF 臂的 `c` 区间很宽（36–63），因为 `noise` 是 60 s 窗、AGC 还在爬。
   用 **均值** 判越界，不要用瞬时值。
4. `c` 是 **stats 口径**（守卫标度）。换算真实码值需 ÷1.24（`docs/02-判据与阈值.md §6`）。
