# 归档轨迹 D84 / D85 / conv_A / conv_B — 2026-10-22

**用途**：`tools/replay_guard.py` 离线回归的输入。把**真实芯片的寄存器变化过程**
按秒级粒度记下来，用来验证判据在真实收敛过程上不会误动作。

**本组轨迹支撑的结论**：`c_rms` 在扰动后会**缓慢**收敛
（readsb 重启后实测 `c = 51→42→32→29`，持续近 1 min），
这段过程中的"过驱动"是**暂态**。判据必须加收敛门禁（近 5 样本极差 ≤3 dB），
否则会在暂态里误判为过驱动并连续降档。

## 格式

```
START 2026-10-22T12:00:03Z tag=D84 pin=0x0a sb=60 st=300
=== PHASE_BASE 2026-10-22T12:00:03Z agcoff+pin 0x0a ===
agcoff rc=0 tries=3
set 0a rc=0 tries=1
12:00:03 BASE 00:a3 01:07 … 0d:09 … 13:0a 14:50 15:01 n=-32.3 p=-5.2 s=0 a=2259/150
```

| 字段 | 含义 |
|---|---|
| `tag` / `pin` / `sb` / `st` | 轨迹名 / 钉的码 / stats 刷新周期(s) / 阶段时长(s) |
| `00:… 15:…` | **16 个寄存器的逐字节快照**（`??` = 单次读失败，属正常，下一行会恢复） |
| `n=` | `stats.noise`（dBFS） |
| `p=` | `stats.peak_signal`（dBFS） |
| `s=` | `stats.strong_signals` |
| `a=x/y` | `stats.accepted` 的两个计数 |

行间隔 **1–2 s**（非严格等距）。阶段以 `=== PHASE_<名> <时间> <做了什么> ===` 起始。

## 从轨迹里能直接看出的事实

- `0d` 恒为 `09`（AGC 在本轨迹全程关闭），`13` 恒为钉入的码 ⇒ 无第三方改写；
- `00`–`02` 每隔几行出现 `??`（单次读失败），说明**单次读不可信**，
  必须靠"连读一致 + 值域白名单"才采信（见 `docs/03-芯片规程.md §5`）；
- `n` 在同一阶段内可摆 0.2–1 dB，`p` 随过顶航班摆到 −1.9 ~ −5.2 dBFS
  ⇒ `peak` 不能当判据（`docs/02-判据与阈值.md §5`）。

## 注意

1. `conv_A.log` 含一行 `unknown mode agcoff`：该轮由 `fc_daemon` 执行，`agcoff` 未执行，
   噪声变化来自 `pin`。`replay_guard.py` 按实际寄存器序列回放。
2. 轨迹里的 `c` 是**守卫标度**（`stats` 口径）。换算真实码值需 ÷1.24
   （见 `../标度标定_20261025/`）。
3. 本组只用于**判据回归**，不是收益证据：采样期间没有做 A/B 对照。
