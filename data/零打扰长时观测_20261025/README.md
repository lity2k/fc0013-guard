# 零打扰长时观测 — 2026-10-25

**问题**：工作点长期在域内时，守卫到底会不会偷偷碰芯片？

**结论**：**不会**。12 份守卫日志、**4 h 35 min** 连续覆盖、**1047 条决策行**，
其中 **1041 条（99.4%）`fc0013=未访问`**；其余 6 条全部是 s1090 相位起管时
"观测源无有效数据，跳过本轮"的冷启动，**没有一条是寄存器访问**。

## 设计

不注入扰动、不改拓扑，让守卫在两台生产机上按 15 s 周期连续跑，
每个相位约 **20 min**，另在部分相位切换拓扑（readsb / s1090）以覆盖两种观测源。

| 项 | 值 |
|---|---|
| 覆盖时段 | 2026-10-25 **01:10:46Z → 05:46:03Z**（4 h 35 min） |
| 守卫日志份数 | **12**（Q1–Q12，其中 Q5、Q11 两机同时） |
| 相位时长 | ~20 min |
| 采样间隔 | 15 s |
| 决策行总数 | **1047** |
| `fc0013=未访问` | **1041（99.4%）** |

## 结果

| 观测 | 值 | 含义 |
|---|---|---|
| 芯片访问次数 | **0** | 全程没有一次 I²C 事务 |
| 写入次数 | **0** | 一次 `0x13` 都没写 |
| `c` 越界样本 | 0 | 工作点始终在 [1.3, 20] 内 |
| 冷启动"不可读" | 6 | s1090 相位第 1 轮，tee CSV 未攒够 30 s，预期行为 |

典型稳态行（readsb 源）：

```
2026-10-25T07:46:24Z STATS src=stats n=-27.9 peak=-3.6 c=5.15 | fc0013=未访问 | OK c=5.15 peak=-3.6 code=0c
```

典型冷启动行（s1090 源，每个相位**只有 1 条**）：

```
2026-10-25T05:00:10Z STATS 不可读（s1090 模式唯一观测源无有效数据：检查管道是否在更新 tee CSV），跳过本轮
```

## 为什么这很重要

守卫的设计语义是"**先判工况、后碰芯片**"。这条语义只有在
"域内真的完全不访问"时才有意义 —— 否则每次轮询都读一遍 `0x13`，
就会与 `readsb`/`fc_daemon` 抢 `DEV_LOCK`、增加 I²C 失败概率、
并在别的进程 rep_off 后读到 `0xff`。

本组日志是这条语义的**直接证据**：`fc0013=未访问` 出现 1041 次，
一次都没有变成 `fc0013=读 d=… i=… l=…`。
