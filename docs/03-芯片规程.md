# 03 — 芯片规程：怎么安全地写 FC0013

守卫用 `ctypes` 直调 `libusb-1.0` 做裸控制传输，**不经 `fc_daemon`、不走 `librtlsdr`**。

## 1. 器件与寻址

| 项 | 值 |
|---|---|
| USB VID / PID | `0x0BDA` / `0x2832`（RTL2832U） |
| FC0013 I²C 从地址 | `0xC6` |
| 跨进程设备锁 | `/tmp/fc_daemon.lock`（与 `fc_daemon` / `fc_dump.py` 共用，避免错位读） |
| 控制传输超时 | 300 ms |

## 2. 控制传输格式（三条红线之一）

| 操作 | bmRequestType | wValue | wIndex | data |
|---|---|---|---|---|
| 写寄存器 | `0x40`（OUT） | `0xC6` | `0x0610` | **`[reg, val]` 两字节** |
| 设读地址 | `0x40`（OUT） | `0xC6` | `0x0610` | `[reg]` 一字节 |
| 读寄存器 | `0xC0`（IN） | `0xC6` | `0x0600` | 1 字节回读 |

**写必须一次传 `[reg, val]` 两个字节。** 拆成两次控制传输（先写地址、再写值）
会让 USB 返回成功而 **I²C 静默失败**，读回仍是旧值。

## 3. 寄存器语义（守卫用到的）

| 寄存器 | 含义 | 守卫的用法 |
|---|---|---|
| `0x0d` | AGC 控制 | bit3 = 1 ⇒ AGC **开**（复位值 `0x01`）；写 **`0x09`** ⇒ AGC **关** |
| `0x13` | IF 增益码 | 低 5 bit 有效，`0x08`…`0x18` 为可用区间，`0x1c` 为实测悬崖码 |
| `0x14` | LNA / 前端 | 只读核对（正常 `0x50`），不写 |
| `0x0c` | 前端偏置 | **只读，不可写**；写 `0xF8`/`0xF9`（bit2=0）会 60 s 内 noise 掉 24 dB、报文归零，**只能物理拔插恢复** |

读回的健康态样本：`0x0d=09`（AGC 关）、`0x13=0a/0c/11`、`0x14=50`。

## 4. 写入顺序（第二条红线）

```
0x0d ← 0x09     关 AGC，写后 20 ms 读回校验
0x13 ← CODE     钉 IF 增益码，写后 20 ms 读回校验
```

**顺序不可颠倒**：AGC 开着时写 `0x13`，芯片会立刻把它改回 AGC 自选的值，
表现为"写成功但读数没变"。

每步**写后 20 ms 读回**，不符重试 ≤ **4** 次。两次写之间至少隔 15 s（防抖）。

## 5. 读的可信性（三重校验 + 白名单）

单次读可能拿到上一状态或全 `0xff`。`read_013()` 的接受条件**全部满足**才采信：

1. 连续 3 次尝试；
2. 值域白名单：`0x0d & 0xF0 == 0`、`0x13 & 0xE0 == 0`（`0x13` 只有低 5 bit 有效）；
3. 再连读两次 `0x0d` / `0x13`，与第一次**逐字节一致**。

任何一条不满足 ⇒ 返回 `None` = **不可信**，**绝不据此写入**。

## 6. 句柄与 repeater（第三条红线）

- **句柄每事务开关**，只有 `libusb` context 常驻。
  常驻句柄跑久会失效：`fc_daemon watch` 实测 **44%** 采样读到 `UNTRUSTED (d=ff i=ff)`。
- 每个事务前都要**重新开 I²C repeater**（开要重试，新进程首拉常失败 ≤5 次）；
  别的进程退出时的 rep_off 会让后续读全部返 `-1`。
- 事务前后加 `flock(DEV_LOCK)`，与其它访问同一颗芯片的进程串行化。

## 7. 绝不走 `librtlsdr`

`rtlsdr_open()` 会跑一遍 tuner init，并可能与 `readsb` 抢设备。
守卫只做裸控制传输：**不 claim 接口、不碰 bulk 端点、不做任何采样**。

⇒ 因此守卫与正在跑的 `readsb` 可以共存（readsb 持有设备句柄做采样，守卫只插 I²C 事务）。
这条也是"域内零打扰"能成立的物理前提：不介入时守卫**连事务都不开**。

## 8. 与其它访问者的互斥

| 对端 | 关系 |
|---|---|
| `readsb`（直采） | 可共存。readsb 启动会 reset tuner、冲掉钉码 ⇒ unit 必须 `BindsTo=readsb.service` + `After=` |
| `rtl_sdr`（s1090 管道） | 可共存。管道由守卫自己拉起，`rtl_sdr` 只做采样 |
| `fc_daemon watch` | **不可同时跑**。它按自己的策略改 `0x0d`/`0x13`，与本守卫抢寄存器，形成互相覆盖 |
| `fc_daemon set` | 与 `--pin` 等价，串行执行即可（共用 `DEV_LOCK`） |

## 9. 自检判据

`--selftest N` 循环写 10 个码（`0x0a/0x0c/0x0f/0x10/0x12/0x14/0x16/0x18/0x1a/0x1c`），
统计"写-读回一致"率：

```
RESULT ok=N fail=0 first_try=N extra_tries=0
```

- `ok < N` ⇒ I²C 链路有问题，先查 `0x13` 是否连读取稳；
- `first_try < N` ⇒ 有重试，链路在边缘，留意；
- ⚠ 自检**真写** `0x13`，末项停在 `0x1c`（悬崖码）⇒ 跑完自动钉回起点码，生产低峰做。
