# 05 — 安装与运维

## 1. 前置检查（每台节点跑一次）

```bash
systemctl is-active readsb                  # 期望：active
python3 -V; ls /lib/*/libusb-1.0.so.0       # 期望：有版本号 + 有库文件
journalctl -u readsb | grep -i tuner        # 期望：Found Fitipower FC0013 tuner
```

三条都满足才继续。第三条不满足说明不是 FC0013，本脚本不适用。

s1090 形态额外检查（`rtl_sdr`、`stream1090` 必须已在 PATH 里，install.sh 只负责 `tee_power`）：

```bash
command -v rtl_sdr stream1090
systemctl cat readsb | grep -- '--net-only'    # 期望：有该参数
```

## 2. 安装（install.sh，一条命令）

安装功能在 `install.sh`，主脚本 `fc0013_guard.py` 是纯控制环、不含安装逻辑。

```bash
# 节点上一条命令；install.sh 本地优先取件（同目录有部署件直接用，缺件才到 GitHub main 下载）：
curl -fsSL https://raw.githubusercontent.com/lity2k/fc0013-guard/main/install.sh -o install.sh
sudo bash install.sh                     # 默认 --mode readsb
sudo bash install.sh --mode s1090        # stream1090 管道拓扑
sudo bash install.sh --align             # 安装后直接做起点码对齐（非交互部署用）
```

离线节点：把 clone 的仓库目录（或 install.sh + `fc0013_guard.py` + `tee_power/`
两个部署件）传上去再执行，效果相同。

install.sh 做五件事：
1. 前置检查：readsb active、python3、libusb-1.0；s1090 模式再查 `rtl_sdr`/`stream1090`；
2. 取件部署 `fc0013_guard.py` 到 `/usr/local/bin/`（`0755`）；
3. s1090 形态取预编译 `tee_power-armhf` 到 `/usr/local/bin/tee_power`
   （不编译；本地与 GitHub 都取不到即退出）；
4. 写 unit 到 `/etc/systemd/system/fc0013-guard.service`，`daemon-reload` + `enable --now`；
5. 询问是否立即做起点码对齐：同意则停守卫 → `--code-scan` → 恢复服务，
   采用后结果写入 `/etc/fc0013-guard.conf`。

幂等，重复跑没有副作用。其它参数：`--uninstall`、`--dry-run`、`-h`。

主脚本降级方案（不装 unit 也能守卫）：直接前台跑 `python3 fc0013_guard.py`。

## 3. 安装后自检

```bash
ssh root@<节点> 'systemctl is-active fc0013-guard && tail -3 /tmp/fc_guard.log'
```

期望 `active` + 每行形如：

```
2026-10-24T09:16:43Z STATS src=stats n=-33.4 peak=-1.2 c=2.73 | fc0013=未访问 | OK c=2.73 peak=-1.2 code=0d
```

`fc0013=未访问` 是**正常态**，不是"没干活"：工作点在域内时它本来就不该碰芯片。

## 4. systemd unit

```ini
[Unit]
Description=FC0013 IF gain guard
After=readsb.service
BindsTo=readsb.service

[Service]
Type=simple
ExecStart=/usr/bin/python3 /usr/local/bin/fc0013_guard.py
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

- `BindsTo=` + `After=` **必须有**：readsb 启动会 reset tuner，把钉码静默冲掉；
  绑生命周期后 readsb 重启，守卫自动跟随重新对齐。
- `Restart=on-failure` **不能改成 always**：锁被占用时脚本**正常退出(0)**
  （打印 `LOCK 已有实例在跑，退出`），`always` 会造成每 5 s 重启的 flapping。
- s1090 形态的 `ExecStart` 末尾带 `--mode s1090`，其余相同。

## 5. 开机 / 重启后核对芯片状态

```bash
systemctl is-active fc0013-guard                               # 期望 active
tail -3 /tmp/fc_guard.log                                      # 期望 OK c=… code=<对齐码>
# code 不是对齐码 ⇒ 对齐一次
python3 /usr/local/bin/fc0013_guard.py --pin 0x0c
```

- 已对齐的机器（有 `/etc/fc0013-guard.conf`）启动即自动写回保存的码；
  未对齐的才需要上面第三步。
- `--pin` 与 `--code-scan` 采用都会（重）写该 conf；删除它（`rm /etc/fc0013-guard.conf`）
  即回到"启动读 `0x13`"。
- readsb 重启后同样核对一次。

## 6. 常用命令

```bash
python3 /usr/local/bin/fc0013_guard.py --once                  # 干跑一轮，只读观测
python3 /usr/local/bin/fc0013_guard.py --pin 0x0c              # 钉码并保存为起点码（关 AGC + 钉 0x13）
python3 /usr/local/bin/fc0013_guard.py --code-scan             # 实测起点码（换硬件后；须先停守卫，约 4–6 min）
python3 /usr/local/bin/fc0013_guard.py --code-scan --adopt     # 同上，但不询问、直接采用
python3 /usr/local/bin/fc0013_guard.py --selftest 20           # I²C 通道自检（真写，低峰做）
systemctl restart fc0013-guard                                 # 不重启机器时恢复
journalctl -u fc0013-guard -n 50                               # 看进程是否反复重启
```

工程模式参数（`--cal` / `--c-min` / `--c-max` / `--raise-ceiling` / `--dry-run`）
会改变工作点或判据，**误用会导致解码率下降甚至报文归零**，只在标定与排障时用。

## 7. 日志格式

```
<时间> START node=… mode=… code=…(--cal 显式指定) cfg={…} write=1
<时间> STATS src=stats n=-27.9 peak=-3.6 c=5.15 | fc0013=未访问 | OK c=5.15 peak=-3.6 code=0c
<时间> STATS src=tee n=-27.84 rows=150 | fc0013=未访问 | OK c=5.19 peak=n/a code=0c
```

| 字段 | 含义 |
|---|---|
| `src=stats` / `src=tee` | 观测源。与部署形态不符 ⇒ 改 `--mode` |
| `n=` | 观测源给的底噪（dBFS） |
| `c=` | `128 × 10^(n/20)`，守卫标度 |
| `fc0013=未访问` | **正常**：不介入就不碰芯片 |
| `fc0013=读 d=… i=… l=…` | 越界了，读了寄存器 |
| `OK` / `UNSTABLE` / `SETTLE` / `ACT` | 判定结果（`ACT` 表示真的写了） |

`n/a` 是 tee 源没提供可比 `peak` 时的正常表示，不是错误。

## 8. 排障顺序

```bash
tail -5 /tmp/fc_guard.log
journalctl -u fc0013-guard -n 50
```

1. `src=` 与部署形态不符 ⇒ 改 `--mode`，**不要**指望它自动回退（严格单源是设计语义）。
2. 每行 `fc0013=未访问` 且 `c` 在 [1.3, 20] ⇒ **正常**。
3. `c` 长期越界但无 `ACT` ⇒ 查收敛门禁：近 5 样本极差 ≤ 3 dB、上次写入后 ≥ 70 s。
4. `systemctl` 显示反复重启 ⇒ 看是否 `LOCK`（另一份在跑）或管道断开（s1090 形态，退出码 3）。
5. 写入反复失败 ⇒ `--selftest 20`；`ok < 20` 说明 I²C 链路有问题，先查 `0x13` 是否连读取稳。
6. s1090 形态下 readsb 报空数据 ⇒ 确认 readsb 在 `--net-only`，且 30001 端口没被别的进程占。

## 9. 卸载

```bash
sudo bash install.sh --uninstall
```

停服务、取消开机自启、删除 unit、脚本与对齐结果 conf。**不改芯片状态** —— 卸载后 `0x0d` 仍停在 `09`
（AGC 保持关闭、IF 码保持最后值）。要恢复成出厂 AGC 行为，手工把 `0x0d` 写回 `0x01`。

## 10. 多节点批量操作

节点表在 `tools/nodes.json`，口令走环境变量 `NODE_SSH_PASS`（不写入文件）。

```bash
export NODE_SSH_PASS=...
python tools/nb_ssh.py exec .85 "tail -3 /tmp/fc_guard.log"
python tools/nb_ssh.py both  "systemctl is-active fc0013-guard"
python tools/nb_ssh.py put   .85 fc0013_guard.py /tmp/fc0013_guard.py
```

- 停守卫时 **kill 与 rm 必须分两次 exec**：`pgrep -f 'fc0013_gua[r]d'` 会匹配到
  `rm /tmp/fc0013_guard.lock` 这条命令自身（路径含子串），放一起会自杀且锁删不掉。
- 日志归档为 `fc_guard.prev.log`，不要删。
