# 01 — 问题与根因：FC0013 内置 AGC 在 ADS-B 上是恒劣项

## 1. 现象

RTL2832U + FC0013 的接收机上，同一副天线、同一台机器、同一时刻，
报文率会在几百 msg/min 到一千多 msg/min 之间大幅摆动，且**没有任何外部扰动**。

把 FC0013 的 IF 增益从"芯片 AGC 自管"改成"固定码值"后，报文率立刻回到高位并稳定。
两机生产态 60 s 交替直测（`data/生产交替直测_20261027/`）：

| 机器 | AGC 态（msgs1min） | 钉码态（msgs1min） | 倍数 |
|---|---|---|---|
| `.84` | 629 / 279 | 1781 / 2080 | **4.25×** |
| `.85` | 522 / 213 | 1989 / 2253 | **5.77×** |

## 2. 根因：检测量与信号形态错配

FC0013 片内 AGC 的检测量是**带内平均功率**，为 DVB-T 一类连续信号设计（占空比 ≈100%）。
ADS-B 是 **120 μs 脉冲、占空比 <1%**：强脉冲到达时平均功率依然很低，AGC 判定"信号弱"，
于是继续抬高 IF 增益 —— 底噪被一路抬进 ADC 削波区，脉冲前沿直接撞顶，报文归零。

这是**结构性错配**，不是参数没调好。片内模拟检测器不可改、I2C 不可见，
只有两条路：关掉 AGC 用固定工作点，或者换芯片。本项目走第一条。

## 3. AGC 的真实控制目标（实测）

AGC 并不"优化分辨率"，它的目标是**把底噪归一化到 ≈ −43.5 ~ −45 dBFS**：

- 起点高于该目标 ⇒ 在 **65–90 s** 内压掉 **12–24 dB**（三次独立复现，跨两台机器）；
- 起点已贴近或低于目标 ⇒ 不动。

对连续信号这是合理设计；对 1% 占空比的脉冲信号，它等于把底噪抬到满量程。
AGC 接管后的实测状态：`c = 33.4 ~ 46.8`（峰值 62.7），peak `−0.9 ~ −1.1 dBFS`，
`strong_signals` 数百至数千/分，报文量掉到 3.3 ~ 12.1 msg/s。
同机钉码态是 20.1 ~ 43.0 msg/s。

## 4. AGC 的工作点彻底不可观测

32 个 I2C 寄存器里**没有任何一位记录 AGC 的当前增益**。
实测：AGC 完成 20–24 dB 的增益调节时，全部 32 个寄存器**逐字节不变**。

⇒ AGC 的调节通道在 I2C 可见域之外，闭环只能靠观测底噪反推（`c_rms`，见 02）。
⇒ 也无法"读出 AGC 当前档位再微调"，只能整体关掉后自己管。

## 5. 失效的代价是不连续的（悬崖，不是斜坡）

增益抬高时底噪上升是缓坡（**+1.55 dB/码**），但报文率不是：

| c（8 bit 满量程码值） | 报文 |
|---|---|
| 20（可行域上界） | 正常 |
| 40 | **全灭** |
| `0x13 = 0x1c` | **实测悬崖码** |

⇒ 一旦越界，损失不是线性的百分之几，而是 100%。
所以判据必须**提前**在上界的一半（20 码）处拦住，留 6 dB 余量。

另有一条不可恢复的坑：`0x0c` 写入 `0xF8`/`0xF9`（bit2=0）⇒ 60 s 内 noise 掉 24 dB、
报文归零，**只能物理拔插恢复**。脚本的寄存器写入因此有值域白名单（见 03）。

## 6. AGC 恒劣的跨工况证据链

不是某个站点、某个时段的偶然。**同一台机、同一段连续采样**内的 BASE→AGCON 对照（E0）
是最干净的一组：没有机器偏置、没有空情分段误差。

`python tools/build_state_table.py` 可直接从归档轨迹复算 E0：

| 轨迹 | BASE（AGC 关）acc/min | AGCON（AGC 开）acc/min | 变化 | `c` 变化 |
|---|---|---|---|---|
| D84 | 2310（n=48） | **58**（n=145） | **−97.5%** | 3.18 → 0.71 |
| D85 | 2257（n=45） | 1396（n=197） | −38.2% | 11.28 → 0.81 |
| CONVA | 3456（n=52） | 2006（n=149） | −41.9% | 10.29 → 0.87 |
| CONVB | 1622（n=49） | 2804（n=139） | +73.0% | 2.20 → 0.86 |

CONVB 段不满足对照条件：`pin` 未生效（回读 `0x13=0x0a`）、BASE 窗仅 95 s、`strong` 全 0
（空情极弱），不计入对照；该段只用于 `c` 分布。

跨机器、跨站点、跨换件前后的九组独立设计，方向全部一致：

（`data/背靠背共存开销_20261025/decompose.md §5`）。故收益一律用长窗口生产态直测：
≥60 s/段、A/B 交替、两机互证。

## 7. 为什么只能关掉 AGC

- `readsb --gain` 与 `rtl_sdr -g` 只给**总增益**（LNA + mixer + IF 的合成），
  FC0013 内部 AGC 仍可接管 IF 级；总增益调低只是把 AGC 的起点挪低，
  AGC 仍会把底噪压回它的目标值。
- 第三方 AGC（`fc_daemon`）走同一颗芯片的同一套寄存器，本质仍是"按平均功率调 IF 增益"，
  同样错配；且它与本守卫**抢同一组寄存器**（见 03 §5）。

⇒ 唯一有效做法：**关掉片内 AGC（`0x0d=09`），自己钉 IF 增益码（`0x13`）**，
并用底噪把工作点守在 ADC 可行域内。这就是 fc0013_guard 的全部职责。
