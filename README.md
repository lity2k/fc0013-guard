# fc0013_guard — FC0013 IF 增益守卫

常驻守护进程，把 RTL-SDR（Fitipower FC0013 调谐芯片）的 **IF 增益工作点维持在 ADC 可行域内**。

工作点正常时它**完全不碰芯片**：既不读也不写 I2C，日志写 `fc0013=未访问`。
只有当底噪工作点越出可行域时才介入，一次 `AGCOFF` 把链路拉回域内。

**实测收益：生产态下报文量 4.25× / 5.77×（两机独立复现）；工作点在域内时的共存开销 ≤2%，与 0 不可区分。**

---

## 1. 它解决什么问题

FC0013 内置 AGC 的检测量是**带内平均功率**（为 DVB-T 一类连续信号设计，占空比 ≈100%）。
而 ADS-B 是 120 μs 脉冲、占空比 **<1%**：强脉冲下平均功率依然很低，AGC 判定"信号弱"，
于是持续抬高 IF 增益 —— 底噪被一路抬进 ADC 削波区，**报文归零**。

这是**检测量与信号形态的结构性错配**，不是参数没调好。片内模拟检测器不可改，
只有两条路：关掉 AGC 用固定工作点，或者换芯片。本项目走第一条。

实测的失效现场（两机 2×2 交叉，各 12 min，注入第三方 AGC）：

| 拓扑 | 无守卫（AGC 接管后） | 有守卫（纠正后） |
|---|---|---|
| readsb 直采 | c = 39.8 ~ 46.8（峰值 62.7），越界 100%，**3.3 ~ 5.8 msg/s** | c = 2.6 ~ 6.6，越界 0%，**20.1 ~ 21.4 msg/s** |
| stream1090 + `--net-only` | c = 33.4 ~ 34.1（峰值 45.4），越界 100%，**9.6 ~ 12.1 msg/s** | c = 2.9 ~ 4.3，越界 0%，**41.3 ~ 43.0 msg/s** |

`c` 是换算成 8 bit 满量程的码值（见下节）。可行域上界 20 码；削波悬崖实测在 **40 码全灭**。

## 2. 判据：一个量，两个边界

```
c_rms = 128 × 10^(noise_dBFS / 20)        可行域 [C_MIN = 1.3, C_MAX = 20.0]
```

- **下界 1.3 码**：量化台阶 / σ ≈ 1 的拐点。确定性回放（同一段真实 UC8，只改有效量化级数）
  ⇒ step/σ ≤ 0.74 时报文 32 条、与满精度逐条重叠 1.000；step/σ = 1.12 起掉 16%，3.16 掉 50%，17.4 归零。
  真机侧：健康工作点 c = 2.93 ~ 11.67，AGC 压缩态 c = 0.71 ~ 0.87 —— 1.3 干净分开两者。
- **上界 20 码**：实测悬崖 40 码全灭，取其 1/2（留 6 dB 余量）。
- **对空情不敏感**：`noise` 是底噪估计，实测 strong 信号 389→873 变化时 noise 仍稳在 −22.0 ~ −21.7 dBFS。

`0x13`（IF 码）**不是**被控量的读数，只作 canary：AGC 完成 20–24 dB 增益调节时，
32 个 I2C 寄存器逐字节不变 —— AGC 的调节通道在 I2C 可见域之外。所以闭环只能用 `c_rms` 反推工作点。

## 3. 它做了什么

每轮（默认 15 s）：

1. **只读观测**：读 readsb `stats.json`（或 stream1090 管道内 `tee_power` 的 `mean_dbfs`），算 `c_rms`。
   这一步**不访问芯片**。
2. **域内 ⇒ 不介入**：`c` 落在 [1.3, 20] 内直接返回，日志 `fc0013=未访问`。
3. **越界 ⇒ 才读芯片**：读 `0x0d`/`0x13`/`0x14`，判定 AGC 是否被第三方开启、`0x13` 是否被改写。
4. **动作**：
   - AGC 开着 ⇒ 关 AGC（`0x0d=09`）+ 写回起点码；
   - `0x13` 被第三方写过 ⇒ 写回起点码；
   - 否则按工况算目标码（升一格 / 按超出量降档）。
5. **写入**：脚本自身用 ctypes 直调 `libusb-1.0` 做控制传输，**不经任何外部二进制**。
   严格顺序 `0x0d=09` → `0x13=CODE`，每步写后读回校验、不符重试。

**动作不对称**（由代价决定）：

| 方向 | 规则 | 原因 |
|---|---|---|
| 降档 | 按超出量算格数，目标 = 域几何中点（5.1 码），地板 `0x08` | 降过头是缓坡：最坏代价 ≈0.166 dB 量化噪声，可逆 |
| 升档 | 一格一格，硬天花板 `0x18` | 升过头是悬崖：c ≥ 40 报文全灭 |

起点码解析顺序：显式 `--cal` > 启动读一次 `0x13` > 默认码 `0x0E`。
逐机的标定起点码在 `deployed.json`，代码内不含任何逐机取值。

## 4. 收益（实测）

| 测量 | 条件 | 结果 | 数据 |
|---|---|---|---|
| **生产态报文量** | 60 s 交替直测 A/B/A/B，两机独立 | `.84` **4.25×**、`.85` **5.77×** | `data/生产交替直测_20261027/` |
| AGC 注入对照（readsb 直采） | 2×2 交叉，12 min/臂 | 交叉平均 **+353%** | `data/交叉注入_readsb_20261024/` |
| AGC 注入对照（s1090 管道） | 2×2 交叉，12 min/臂 | 交叉平均 **+292%** | `data/交叉注入_s1090_20261024/` |
| **域内共存开销** | 14 相位 × 10 min 背靠背 | msg/s 效应 −0.34%（readsb）/ +1.95%（s1090），**均 ≤2%，与 0 不可区分** | `data/背靠背共存开销_20261025/` |
| 纠正延迟 | 注入到落回域内 | 86 ~ 117 s（来自收敛门禁，不是轮询周期） | 同上两轮 |

**域内零打扰**（日志级直接证据）：

- 背靠背 14 相位：678 条决策行中 **672 条 `fc0013=未访问`**，芯片一次没写；
- 4 h 35 min 长观测（12 份日志，20 min/相位）：1047 条中 **1041 条 `fc0013=未访问`**
  （其余 6 条全是 s1090 起管首轮"观测源无有效数据，跳过"，没有一条是寄存器访问）。

**测量口径**：收益必须用长窗口（≥60 s/段）的生产态 A/B 交替直测；
无守卫时 `.84` 生产段 279 ~ 629 报文/min，守卫段 1781 ~ 2080。

## 5. 安装

**一条命令**（`install.sh` 统一安装，主脚本不含安装逻辑）：

```bash
# 把发布目录整体传到节点后，在节点上执行：
sudo bash install.sh                     # 默认 --mode readsb
sudo bash install.sh --mode s1090        # stream1090 管道拓扑
```

install.sh 依次完成：前置检查（readsb active / python3 / libusb-1.0）→
部署 `tee_power`（预编译优先，`--build` 现场编译）→ 部署主脚本到 `/usr/local/bin` →
写 systemd unit（`BindsTo=readsb.service`）并 enable + start。
幂等。卸载：`--uninstall`。

`--mode s1090` 下守卫自建 `rtl_sdr | tee_power | stream1090` 管道并把数据转发给 readsb 的 30001 端口，
**不需要 socat、不需要另写管道脚本**（`tee_power` 见 `tee_power/README.md`）。
启动前会检查 readsb 是否真在 `--net-only` 运行、各程序是否可执行，不满足就打印处理办法并退出。

前置检查（三条，节点上各跑一次）：

```bash
systemctl is-active readsb                  # 期望：active
python3 -V; ls /lib/*/libusb-1.0.so.0       # 期望：有版本号 + 有库文件
journalctl -u readsb | grep -i tuner        # 期望：Found Fitipower FC0013 tuner
```

安装后自检：

```bash
ssh root@<节点> 'systemctl is-active fc0013-guard && tail -3 /tmp/fc_guard.log'
```

期望：`active` + 日志每行形如

```
2026-10-24T09:16:43Z STATS src=stats n=-33.4 peak=-1.2 c=2.73 | fc0013=未访问 | OK c=2.73 peak=-1.2 code=0d
```

`fc0013=未访问` 是正常态 —— 工作点在域内时它本来就不该碰芯片。

## 6. 验证

```bash
python tools/replay_guard.py                    # 离线回归：注入场景 + 真实轨迹回放 + I2C 传输层自检（改判据后必跑）
python3 fc0013_guard.py --once                  # 节点上干跑一轮（只读观测，打印判定后退出）
python3 fc0013_guard.py --selftest 20           # I2C 通道自检（真写 0x13，基线 ok=20 fail=0 first_try=20）
```

## 8. 适用范围与已知限制

- 面向 **RTL2832U + FC0013**（其它调谐器的寄存器语义不同，不适用）。
- 只保证工作点**在可行域内**，不追求"最优灵敏度"；吞吐调优不在职责内。
  工作点的最优搜索收益硬上限约 0.3 dB，故本项目不部署连续追踪器。
- AGC 自选的工作点若**仍在可行域内**（实测 `0x13=0x1c`、c = 7.4），守卫**不纠正** —— 它只管越界。
  生产态要靠开机时的 `--pin <码>` 强制对齐。
- 芯片回上电默认态时守卫不介入 ⇒ 开机 / USB 重新枚举后核对日志 `code=`，不符则 `--pin <码>` 对齐
  （见 `docs/05-安装与运维.md` §5）。
- 两种观测源的物理窗口不等价：stats 源 [1.05, 16.1]、tee 源 [1.3, 20]（真实码值口径）。
  现工作点真值 ≈ 4.0，两端余量 5–6 dB；**收紧阈值前必须先统一观测源口径**。
- 已知缺口：`peak` 贴顶 + `strong > 0` 但 `c` 仍在域内的**轻度过驱**不被介入
  （`peak` 只作 −0.2 dBFS 饱和兜底）。跨机只能按 `c_rms` 对齐工作点，不能按 `0x13` 码（同码跨件差 2–3 dB）。
